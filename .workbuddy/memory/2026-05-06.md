- **单文件拆分为多模块**：将 `index.html`（约 2674 行）拆分为 4 个文件，职责清晰：
  - `index.html`（304 行）：HTML 结构 + 入口 + VR 初始化 + 动画循环
  - `js/core.js`（507 行）：常量配置 + STATE 状态对象 + Three.js 场景/渲染器/相机 + 灯光 + 天空系统 + 云朵 + 共享 Group 容器
  - `js/game.js`（755 行）：子弹系统 + 气球/骑士敌人 + 碰撞检测 + 波次生成 + 抽卡系统 + 如来神掌 + 死亡重开 + 碎片/粒子特效
  - `js/vr.js`（474 行）：Web Audio 音效 + GLB 模型加载 + VR 手柄设置 + AK48 枪支挂载 + 输入处理 + 摇杆移动/射击/退出 + 左右手腕 UI 面板
  - 模块间通过 ES Module `import/export` 连接，`core.js` 作为底层共享层被所有模块导入。`game.js` 通过运行时注入 `setAudio(vr)` 获取音效函数，避免循环依赖。

- **修复 PICO 4 黑屏 + 退出失效问题**：
  - 根因1：`import * as` 语法在 PICO 4 浏览器（Chrome/105）上有兼容性 Bug（已知问题）。将 `index.html` 和 `vr.js` 中的 `import * as game/vr` 改为命名导入聚合对象 `GameAPI` / `VrAPI`。
  - 根因2：`game.js` 的 `clearChoiceCards` 中直接调用了 `attachBuddhaPalmToLeft()`，但该函数在 `vr.js` 中定义，`game.js` 并未导入它（模块拆分后作用域隔离）。在严格模式下会抛出 `ReferenceError`，导致 `setTimeout` 回调异常。修复方式：添加 `setVR(vr)` 运行时注入，由 `index.html` 初始化时注入 VR 模块引用。
  - 根因3：`game.js` 和 `vr.js` 形成了循环依赖（`game.js` → `attachBuddhaPalmToLeft` ← `vr.js` → `shootBullet` ← `game.js`）。通过运行时注入消除循环依赖。
  - 防护措施：给 `animate()` 和 `initScene()` 添加 try-catch，确保即使逻辑层异常，`renderer.render(scene, camera)` 仍然执行，错误信息也会显示在 DOM 的 `#status-msg` 中，便于在 PICO 4 上排查问题。
